# No Comments in SQL
Never include comments in the generated SQL queries. All SQL code should be comment-free to ensure clarity and simplicity.

# Unique Page Views
"Unique page views" refers to the number of unique sessions, identified by the unique_session_id column, during which a specific page was viewed at least once, regardless of how many times the page was loaded or reloaded in the same session.


# Specific Page Targeting
When targeting specific pages, use the page_location column as the filter for those pages.


# Page Views Selection
When querying page views, select page_view under the event_name column.
Filter results by ensuring the event_name column has the value page_view.


# WHERE Statement Rules
Use URL slugs with the cleaned_page_location column, e.g., WHERE cleaned_page_location = "/youth-mobility". Do not use the full URL with the domain.
Use full URLs with the domain in the page_location column, e.g., page_location = "https://www.gov.uk/youth-mobility". Do not use the slug URL only.


# Ordering Results
If a query is likely to return a list of results, order by the number of page views by default, unless specified otherwise.


# User Journey
Distinguish between internal and external sources:
Internal sources come from the www.gov.uk domain and are reflected in the page_referrer column.
External sources are other domains (e.g., Google, Bing) and are reflected in the session_source column.


# Additional Context
For traffic source analysis, use the page_referrer column to identify the origin of navigation within the same domain.
Use the page_location column to identify the target of user interactions, such as clicks.
For date filtering, use the _TABLE_SUFFIX to specify the range, facilitating efficient data retrieval.



# Device Type Identification
To identify the type of device that generated an event or that a user uses, refer to the "category" column. The "category" column can contain the following case-sensitive values:

null
desktop
tablet
smart tv
mobile


# Search Term Queries
When querying for search terms, use the search_term column, which contains the keywords entered by users in the search box. To analyze which search terms led to specific pages, focus on the select_item event in the event_name column.


# Event Filtering for Search
Use event_name = 'select_item' to identify events where users clicked on a search result to navigate to a specific page. This event indicates that the user selected a result from the search results page.

# Target Page Identification
To determine the destination page that users navigated to, filter using the link_url column, which contains the full URL of the page that was opened from the search results.

# Search Results Page Context
To ensure the event occurred on the search results page, filter by cleaned_page_location = '/search/all', which represents the search results page path.


# Search Event Analysis
To identify pages where users may struggle to find content, focus on the search event in the event_name column. This event is triggered when users perform a search using the search bar on any page of the website.

# Search Frequency by Page
To determine which pages have the highest number of searches, group the results by the cleaned_page_location column and count the number of search events. Pages with the most searches may indicate where users struggle to find information.

# File Download Event
To track file downloads, use the file_download event in the event_name column. This event is triggered whenever a user downloads a file from the website.

# Identifying Downloaded Files
The link_url column contains the URL of the downloaded file. Use this column to identify which files were downloaded during the file_download event.

# Page Context for Downloads
To understand the context of where a file was downloaded, use the cleaned_page_location column, which specifies the page from which the file was downloaded.
